# spec2openapi v0.6.0

[English release notes](v0.6.0.md)

검증 릴리즈다. FastMCP 변환 가능성 계약과 `x-soap` 런타임 계약이 이제
실행 가능하고 근거를 인용하는 체크 목록이 됐다 — 라이브러리 API와
기계가 읽는 CLI 출력 양쪽으로 제공된다.

## 하이라이트

**`verify` — 구조화된 라이브러리 수준 검증.** 지금까지
`spec2openapi validate`가 증명할 수 있던 것들은 전부 CLI 안에 갇혀
있었다. 이제 공개 API가 됐고, Swagger 변환 스펙과 WSDL 변환 스펙에
똑같이 동작한다:

```python
spec = spec2openapi.convert_swagger(legacy)      # 또는 convert_wsdl(...)

report = spec2openapi.verify(spec)
report.ok          # 실패한 체크 없음
report.complete    # 건너뛴 체크 없음 — 딥 체크가 실제로 돌았음
report.to_dict()   # JSON 보고서: 체크별 id, 상태, 위치, 근거 인용
```

- **체크 21종**: 문서 형태, MCP tool 이름 규칙, tool description 존재
  여부, 그리고 `x-soap` 계약 전체 — soapVersion 유효성,
  header/fault/본문의 스키마 참조 해석, substitution/choice 마커
  정합성, SOAP+REST 혼합 감지. 선택 의존성이 설치되어 있으면
  `openapi-spec-validator`와 실제 `FastMCP.from_openapi()` 인메모리
  라운드트립까지 실행된다.
- **보고 규율**은 공식 MCP conformance 스위트의 설계에서 가져왔다.
  모든 체크 id가 모든 보고서에 등장하므로 "검사해서 통과"와 "검사하지
  못함"(`skip`)이 항상 구분되고, warn/fail 수준은 인용한 요구사항에서
  유도되며, 각 결과에는 규범 근거가 붙는다 — tool 이름의 SEP-986,
  OpenAPI 명세, 문서화된 FastMCP 동작, 그리고 이 프로젝트 자신의
  `x-soap` 계약.
- **`verify`는 예외를 던지지 않는다.** 손상됐거나 적대적이거나 깊게
  중첩된 문서도 예외가 아니라 보고서를 만든다 — 체크 단위 가드와
  반복문 기반 트리 순회가 이 계약을 구조적으로 보장한다.
- `check_fastmcp_ready`는 그대로다(체크 집합·형태·메시지 동결).
  내부적으로 같은 엔진에 위임할 뿐이다.

**`validate --format json` — 같은 보고서를 CLI에서.** 기본 텍스트
출력은 익숙한 형태를 유지하고, JSON 모드는 `verify()` 보고서 전체를
출력해 CI 파이프라인이 특정 체크 id로 게이트할 수 있게 한다. 의도된
동작 변화 하나에 유의: `validate`는 이제 이전에는 통과하던 `x-soap`
계약 위반과 3.x가 아닌 문서에도 실패(exit 1)하고, warn 수준 발견은
`note:` 줄로 출력한다.

## 설치

```bash
pip install spec2openapi          # 변환기 + CLI (Python 3.10+)
pip install "spec2openapi[mcp]"   # + SOAP 브리지 (SOAP 스펙 서빙에 필수)
```
