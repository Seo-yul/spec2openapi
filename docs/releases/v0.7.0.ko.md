# spec2openapi v0.7.0

[English release notes](v0.7.0.md)

변환은 원본에 충실하지만, 원본에 없던 내용을 지어낼 수는 없다. 아무것도
문서화하지 않은 WSDL은 아무것도 설명하지 않는 tool을 만들고, 그것을
호출하는 agent는 짐작에 기댈 수밖에 없다. `spec2openapi agentize`가 그
빈틈을 LLM으로 채운다 — 결정론적 경로와는 철저히 분리해서, 이 도구가
지금까지 해온 보장은 그대로 유지한 채로.

## 하이라이트

**`agentize` — LLM이 쓰되, 목줄은 짧게.**

```bash
pip install 'spec2openapi[llm-anthropic]'
export ANTHROPIC_API_KEY=...          # 또는: ant auth login

spec2openapi agentize petstore.json --dry-run          # 무엇이 바뀔지 미리 본다
spec2openapi agentize petstore.json -o petstore.openapi.json

# WSDL — 명령은 동일하다; 변환이 먼저 일어날 뿐이다
spec2openapi agentize service.wsdl -o service.openapi.yaml
```

원본이 비워둔 곳을 채운다: 스키마 property 설명, operation summary,
parameter 설명. `--rename-tools`는 기계가 생성한 `operationId`를 모델이
읽을 수 있는 이름으로 바꾸고(`delete_pets_petId` → `delete_pet`),
`--self-check`은 완성된 tool payload를 다시 읽어 여전히 모호한 operation을
보고한다.

모델에게는 일에 필요한 만큼의 권한만 준다.

- **모델은 문자열만, 오직 문자열만 돌려준다.** 그것을 어디에 쓸 수
  있는지는 JSON Pointer에 대한 정규식 화이트리스트가 정한다. `type`,
  `required`, `$ref`, `xml`, 그리고 `x-soap` 런타임 계약에는 어떤
  응답으로도 도달할 수 없다 — 읽고 있는 스펙을 통해 프롬프트 인젝션된
  응답이라도 마찬가지다.
- **모든 제안은 근거 등급을 달고 온다**(`named` / `documented` /
  `inferred` / `speculative`). 근거 없는 추측은 요청하지 않는 한 폐기한다.
  자신 있게 틀린 enum 설명은 agent를 잘못된 호출로 이끄는데, 이는 설명이
  없는 것보다 나쁘다.
- **`verify()`를 통과하지 못하면 아무것도 쓰지 않는다.** 적용 후 계약
  전체를 다시 돌리고, 하나라도 실패하면 실행을 중단하며 파일을 쓰지 않는다.
- **결정론적 작업이 먼저 돈다.** 문서가 이미 답하고 있는 것을 모델에게
  묻는 일은 없다.
- **출력 언어는 묻지 않고 정한다** — 첫 호출 전에 스펙 자신의 산문에서
  판정하고, preflight 줄에 함께 출력한다. 모델에게 "문서에 쓰인 언어로
  맞춰라"라고 맡겼더니 실행마다 답이 달라졌다.

무엇이 생성됐는지는 루트 `x-s2o.agentize`에 JSON Pointer로 기록된다 —
FastMCP가 tool payload에 그대로 복사하는 스키마 노드 바깥이다. 그래서
재실행은 멱등이고, 리뷰어는 모델이 쓴 문장을 나머지와 구분할 수 있다.

`--dry-run`은 API를 호출하지 않고 자격증명도 필요 없다. 기본 설치에
의존성이 늘지 않으며, `import spec2openapi`는 두 SDK 중 어느 것도 끌어오지
않는다.

## 이번 릴리즈의 나머지

**변환 정확성.** 변환 결과물 자체가 달라지는 수정이 여럿이라,
`agentize`를 전혀 쓰지 않고 `convert_swagger` / `convert_wsdl`만 쓰는
경우에도 영향이 있다.

- `allOf`를 포함한 형제 키를 가진 `$ref`가 더 이상 소리 없이 사라지지
  않는다.
- `type`에 접을 수 없는 자리에서도 `nullable`이 3.1 변환을 살아남는다 —
  `allOf`/`$ref`로 감싼 스키마, enum만 있는 스키마, type이 없는 스키마는
  이제 null을 잃는 대신 `anyOf: [스키마, {type: null}]`이 된다.
- 3.1 변환이 이름 기반으로 불투명 여부를 정하지 않고 이름-키 map
  (`responses`, `headers`, 컴포넌트 map)을 순회한다. `nullable`을 담은
  `default` 응답이 변환되지 않은 채 출력에 도달하던 문제가 없어졌다.
- 이름이 문자 그대로 `nullable`, `enum`, `exclusiveMinimum`인 property가
  더 이상 훼손되지 않는다. `properties` 안의 키는 키워드가 아니라 이름이다.
- XSD enumeration과 수치 경계가 기반 타입으로 변환되어, `xs:int`에 대한
  제약이 `{type: integer, enum: ["1"]}` 같은 충족 불가능한 스키마를 만들지
  않고, 64비트 경계도 정밀도를 잃지 않는다.
- 다중 타입 스키마가 `type: file` 및 array의 `items` 보정보다 먼저
  정리되므로, 검증에 실패하는 문서를 내보내지 않는다.

**SOAP 브리지의 정직성.** 본문이 Fault가 아닌 정상 envelope인 HTTP
4xx/5xx 응답을 HTTP 200으로 답하고 있었다 — 실행되지도 않은 operation이
성공했다고 모델에게 말한 셈이다. 이제 실제 상태 코드와 fault payload를
돌려준다. 선언된 `soap:header` 파트는 버리지 않고 직렬화하며
(`BridgeOptions(soap_headers=...)` 또는 `SPEC2OPENAPI_SOAP_HEADERS`),
3.1 스펙에서도 응답 값을 변환하고, 버전 정규화를 공유해 framing과
네임스페이스가 어긋날 수 없게 했다.

**보안.** 신뢰할 수 없는 번들을 변환하는 경우를 위한 세 건이다. 번들 멤버
이름을 백슬래시 정규화 **이후에** 검증하고 모든 쓰기를 절대경로 포함
검사로 가둔다. 압축 해제 크기 상한을 해제가 끝난 뒤가 아니라 **해제하는
동안** 적용한다. 그리고 값이 비어 있는 `SPEC2OPENAPI_VERIFY`가 더 이상
TLS 인증서 검증을 끄지 않는다.

## 호환성이 깨지는 변경

`x-soap-choice` 항목이 개별 엘리먼트가 아니라 **branch**를 서술한다.
`members[]` 항목은 흔한 단일 엘리먼트 branch에서는 여전히 이름 하나지만,
branch 자체가 `xsd:sequence`인 경우에는 이름 목록으로 나타난다. 그
엘리먼트들은 함께 묶여 있어 통째로 선택되거나 통째로 빠진다. 이전에는
개별 멤버로 평탄화되어, XSD가 요구하는 payload를 브리지가 거부했다.

동봉된 런타임과 `x-soap.choice` 검증 체크는 두 형태를 모두 이해한다.
`x-soap` 계약을 직접 구현했다면 `members[]` 항목이 이제 리스트일 수 있다 —
처리하지 않으면 그 branch가 서로 배타적인 여러 선택지로 읽힌다.

`spec2openapi validate`도 이제 `x-soap` 계약 위반과 3.x가 아닌 문서에
대해 종료 코드 1로 실패한다(이전에는 통과했다). 경고 수준 항목은 `note:`
줄로 출력된다. 변환된 스펙을 검증하는 파이프라인이 초록에서 빨강으로
바뀔 수 있는데, 그 문서는 이미 깨져 있던 것이다.

## 설치

```bash
pip install --upgrade spec2openapi

# 선택 extra
pip install 'spec2openapi[mcp]'             # SOAP 브리지 + FastMCP 런타임
pip install 'spec2openapi[llm-anthropic]'   # agentize, Claude
pip install 'spec2openapi[llm-openai]'      # agentize, OpenAI
```

Python 3.10+. 자세한 내역은 [CHANGELOG.md](../../CHANGELOG.md)에 있다.
