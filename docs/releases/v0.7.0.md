# spec2openapi v0.7.0

[한국어 릴리즈 노트](v0.7.0.ko.md)

`spec2openapi agentize` fills the descriptions a source spec leaves
empty with an LLM — kept strictly apart from the deterministic path, so
the guarantees the rest of the tool makes still hold.

## Highlights

**`agentize` — LLM-written descriptions, on a short leash.**

```bash
pip install 'spec2openapi[llm-anthropic]'
export ANTHROPIC_API_KEY=...          # or: ant auth login

spec2openapi agentize petstore.json --dry-run          # what would change
spec2openapi agentize petstore.json -o petstore.openapi.json

# WSDL — the same command; conversion happens first
spec2openapi agentize service.wsdl -o service.openapi.yaml
```

It fills what the source left empty: schema property descriptions,
operation summaries, parameter docs. `--rename-tools` also replaces
machine-generated `operationId`s with names a model can read
(`delete_pets_petId` → `delete_pet`), and `--self-check` re-reads the
finished tool payload and reports operations that are still ambiguous.

The model is given as little authority as the job allows:

- **It returns strings, and only strings.** Where they may be written is
  a regex whitelist over JSON Pointers. `type`, `required`, `$ref`,
  `xml`, and the `x-soap` runtime contract are unreachable by any
  response — including one that has been prompt-injected through the
  spec it is reading.
- **Every suggestion carries a grounding grade** (`named` /
  `documented` / `inferred` / `speculative`), and ungrounded guesses are
  dropped unless you ask for them.
- **Nothing is written unless `verify()` still passes.** The full
  contract re-runs after applying; any failure aborts the run and writes
  nothing.
- **Deterministic work runs first**, so the model is never asked what
  the document already answers.
- **The output language is decided, not asked** — detected from the
  spec's own prose before the first call, and printed with the preflight
  line. `--language` overrides it.

What was generated is recorded under root `x-s2o.agentize` as JSON
Pointers — outside the schema nodes, which FastMCP copies verbatim into
tool payloads. Re-runs are idempotent, and a reviewer can tell
model-written prose from the rest.

`--dry-run` makes no API call and needs no credentials. The base install
gains no dependencies, and `import spec2openapi` pulls in neither SDK.

## Also in this release

**Conversion correctness.** Several defects changed what converted
documents look like, so this affects `convert_swagger` / `convert_wsdl`
callers who never touch `agentize`:

- A `$ref` with sibling keys including `allOf` is no longer silently
  dropped.
- `nullable` survives the 3.1 conversion where it cannot fold into a
  `type` — `allOf`/`$ref`-wrapped, enum-only, and type-less schemas now
  become `anyOf: [schema, {type: null}]` instead of losing the null case.
- The 3.1 conversion walks name-keyed maps (`responses`, `headers`,
  component maps) rather than deciding opacity by key name, so a
  `default` response carrying a `nullable` schema no longer reaches the
  output unconverted.
- A property literally named `nullable`, `enum`, or `exclusiveMinimum` is
  no longer mangled: keys inside `properties` are names, not keywords.
- XSD enumerations and numeric bounds convert to the base type, so a
  restriction on `xs:int` no longer yields `{type: integer, enum: ["1"]}`,
  and 64-bit bounds keep their precision.
- Multi-type schemas collapse before the `type: file` and
  array-needs-`items` fixups, so they no longer emit invalid documents.

**SOAP bridge honesty.** An HTTP 4xx/5xx response whose body was a
well-formed non-Fault envelope was answered as HTTP 200 — telling the
model an operation that never ran had succeeded. It now returns the real
status with a fault payload. Declared `soap:header` parts are serialized
instead of dropped (`BridgeOptions(soap_headers=...)` or
`SPEC2OPENAPI_SOAP_HEADERS`), response values are coerced on 3.1 specs
too, and version normalization is shared so framing and namespace cannot
disagree.

**`minify_for_mcp`.** `drop_value_examples=True` also removes
parameter-level `example` values, which FastMCP copies into the tool's
input schema.

**Security.** Three hardening fixes for callers converting untrusted
bundles: bundle member names are validated after backslash normalization
and every write is confined by an absolute-path containment check; the
uncompressed-size cap is enforced *during* decompression rather than
after; and a set-but-empty `SPEC2OPENAPI_VERIFY` no longer disables TLS
certificate verification.

## Breaking changes

**FastMCP 4.** The `[mcp]` extra requires FastMCP 4 and uses `httpx2` in
place of `httpx`. `SoapBridgeTransport` is an `httpx2.AsyncBaseTransport`;
a client you build around it is an `httpx2.AsyncClient`. TLS certificates
for SOAP and REST calls are checked against the operating system's trust
store; with `SPEC2OPENAPI_TRUST_ENV` on, `SSL_CERT_FILE` / `SSL_CERT_DIR`
take precedence.

`x-soap-choice` entries now describe **branches**, not individual
elements. A `members[]` entry is still a bare property name for the usual
single-element branch, but a branch that is itself an `xsd:sequence`
appears as a list of names: those elements belong together and are chosen
or omitted as a unit. Previously they were flattened into separate
members, so the bridge rejected payloads the XSD requires.

The bundled runtime and the `x-soap.choice` verification check understand
both shapes. If you implemented the `x-soap` contract yourself, a
`members[]` entry may now be a list — handle it, or the branch will read
as several mutually exclusive options.

`spec2openapi validate` also now exits 1 on `x-soap` contract violations
and non-3.x documents that previously passed. Warn-level notes print as
`note:` lines. A pipeline that validates converted specs may go from
green to red on a document that was already broken.

## Install

```bash
pip install --upgrade spec2openapi

# optional extras
pip install 'spec2openapi[mcp]'             # SOAP bridge + FastMCP 4 runtime
pip install 'spec2openapi[llm-anthropic]'   # agentize, Claude
pip install 'spec2openapi[llm-openai]'      # agentize, OpenAI
```

Python 3.10+. Full detail in [CHANGELOG.md](../../CHANGELOG.md).
