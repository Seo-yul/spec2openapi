# spec2openapi v0.6.0

[한국어 릴리즈 노트](v0.6.0.ko.md)

A verification release: the FastMCP-readiness contract and the `x-soap`
runtime contract are now executable, citable checks — available as a
library API and as machine-readable CLI output.

## Highlights

**`verify` — structured, library-level verification.** Everything
`spec2openapi validate` could prove was previously locked inside the
CLI; it is now a public API that works on Swagger- and WSDL-converted
documents alike:

```python
spec = spec2openapi.convert_swagger(legacy)      # or convert_wsdl(...)

report = spec2openapi.verify(spec)
report.ok          # no failed checks
report.complete    # nothing skipped — the deep checks actually ran
report.to_dict()   # JSON report: per-check id, status, location, refs
```

- **21 checks**: document shape, MCP tool-name rules, tool-description
  presence, and the full `x-soap` contract — soapVersion validity,
  schema-reference resolution for headers/faults/bodies,
  substitution/choice marker integrity, and mixed SOAP+REST detection.
  With the optional deps installed, `openapi-spec-validator` and a real
  `FastMCP.from_openapi()` in-memory round-trip run as well.
- **Reporting discipline**, adopted from the official MCP conformance
  suite's design: every check id appears in every report, so "checked
  and passed" is always distinguishable from "could not check"
  (`skip`); warn/fail levels derive from the cited requirement; and
  each result carries normative references — SEP-986 for tool names,
  the OpenAPI specification, documented FastMCP behavior, and this
  project's own `x-soap` contract.
- **`verify` never raises.** Malformed, adversarial, or deeply nested
  documents produce reports, not exceptions — per-check guards and
  iterative tree walkers enforce the contract structurally.
- `check_fastmcp_ready` is unchanged (frozen check set, shape, and
  messages) and now delegates to the same engine.

**`validate --format json` — the same report on the CLI.** The default
text output keeps its familiar shape; the JSON mode prints the full
`verify()` report for CI pipelines that want to gate on specific check
ids. Note the intentional behavior change: `validate` now also fails
(exit 1) on `x-soap` contract violations and non-3.x documents that
previously passed, and prints `note:` lines for warn-level findings.

## Install

```bash
pip install spec2openapi          # converter + CLI (Python 3.10+)
pip install "spec2openapi[mcp]"   # + SOAP bridge (required to serve SOAP)
```
