# spec2openapi v0.5.0

[한국어 릴리즈 노트](v0.5.0.ko.md)

An MCP-surface release: a new optional post-processor makes the tool
payloads FastMCP serves smaller and more informative, and the docs now
cover controlling the tool *count* on large services.

## Highlights

**`minify_for_mcp` — shrink and enrich what the model actually sees.**
When a spec is served over MCP, the LLM never reads the OpenAPI
document; it sees each tool's `name`, `description`, `inputSchema`, and
`outputSchema`. The new post-processor operates on exactly that surface
— the conversion pipeline is unchanged, users opt in with one call:

```python
spec = spec2openapi.convert_swagger(legacy)      # or convert_wsdl(...)
spec = spec2openapi.minify_for_mcp(spec, enrich=("errors", "examples"))
```

- **Shrink**: foreign vendor `x-*` extensions are stripped from schema
  subtrees — the locations FastMCP copies verbatim into tool schemas —
  while everything a runtime or reader needs survives (`x-soap*`, `xml`
  annotations including `x-text`, `x-s2o`, `x-fastmcp-*`, the
  lossy-preservation companions `x-pattern`/`x-collectionFormat`, and
  documentation-bearing extensions such as `x-enum-varnames`;
  `keep_extensions=` protects custom ones). Opt-in trims:
  `max_description`, `drop_value_examples`.
- **Enrich**: facts the MCP tool shape drops are folded back into the
  one channel the model always sees. `"errors"` adds a terse
  `Errors: 404 (order not found); 409 (duplicate).` line from the error
  responses; `"examples"` folds request/response payload examples as
  compact one-line JSON and hoists parameter-level `example` values into
  the parameter schema, where they become visible in `inputSchema`. Only
  facts already present in the document are used — nothing is invented,
  and re-runs never duplicate a fold.

For any option combination the output stays a valid, FastMCP-ready
OpenAPI document and serves identically (byte-identical SOAP
envelopes); the function is deterministic and idempotent, and what was
removed or folded is summarized under `x-s2o.minify`. A hardening audit
covered real-world document shapes — cyclic and alias-shared schemas,
OpenAPI 3.1 subschema keywords, wildcard error ranges, hostile argument
shapes — each pinned by a dedicated regression test, plus a leak-map
test that fails loudly if a FastMCP upgrade changes which spec locations
reach tool payloads.

**Tool-count control, documented.** On a large service the dominant
context cost is the *number* of tools, not their size: MCP clients load
the entire `tools/list` result into the model's context on every
request. The READMEs now document the verified pattern for serving a
subset — FastMCP route maps pass straight through
`from_openapi_spec(...)`, the SOAP bridge keeps working (excluded
operations never receive a call), and WSDL-converted specs already tag
every operation with its service name, so service-per-agent subsets
need no extra tagging.

## Install

```bash
pip install spec2openapi          # converter + CLI (Python 3.10+)
pip install "spec2openapi[mcp]"   # + SOAP bridge (required to serve SOAP)
```
